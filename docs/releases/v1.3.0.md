# v1.3.0 — MCP SDK 2 with legacy stdio compatibility

The Python server migrates from FastMCP to MCPServer and requires
`mcp[cli]>=2.3,<3`, locked at 2.3.0. This SDK change is separate from wire
protocol selection: existing SDK 1 clients continue to use initialization and
protocol 2025-11-25; modern clients can discover the server or make their first
2026-07-28 request without an initialization handshake.

## Compatibility

| Client | Server / protocol | Validation |
| --- | --- | --- |
| Python SDK 1.27.2 and 1.30.0 | Published perfdigest-mcp 1.2.1 / 2025-11-25 | Actual registry baseline, all seven tools |
| Python SDK 1.27.2 and 1.30.0 | perfdigest-mcp 1.3.0 / 2025-11-25 | Same schemas and deterministic report payloads |
| Python SDK 2.3.0, legacy mode | perfdigest-mcp 1.3.0 / 2025-11-25 | Real stdio calls and server identity |
| Python SDK 2.3.0, auto or modern mode | perfdigest-mcp 1.3.0 / 2026-07-28 | Discovery, direct requests and seven-tool contract |
| Raw JSON-RPC | perfdigest-mcp 1.3.0 / 2026-07-28 | No-handshake first call, metadata and version rejection |

All seven tool names and parameters remain unchanged. Format is required;
missing metrics remain absent rather than becoming zero. Digesting saved reports
remains host-independent, capture advice remains platform-gated, and raw_ref
provenance and lazy expansion remain available. The server remains a translator,
not a performance judge.

Synchronous tool handlers now run on SDK worker threads. The existing cache
lock is retained and exercised by concurrent reads. Deliberate report/input
errors keep their corrective text; unexpected crashes retain SDK 2 redaction.
Server identity now reports the perfdigest-mcp distribution version.

v1.2.1 is the release baseline. Its previously published dispatch tags,
summary distinct-name coverage and stable totals, comparison domains and usage
caveats (#32/#33) remain intact. Those changes are not attributed to this SDK
migration. Applications requiring the Python SDK 1 dependency can retain
`perfdigest-mcp==1.2.1`; ordinary legacy MCP clients can connect to v1.3.0.

## Validation and limits

The existing Python 3.10–3.14 and 3.14t matrix remains on Linux, macOS and
Windows. The 17 installable cells exercise 229 tests, with 16 native-report
fixture skips, plus genuine isolated legacy clients. Clean-wheel jobs check
Python 3.10 and 3.14. **Windows 3.14t is NOT EXECUTED** because pywin32 312 lacks
an applicable distribution. Only that exact install failure is classified;
all other install/test failures remain strict. A green classifier job is not
successful Windows 3.14t test coverage.

HTTP/SSE deployment, hardware capture and new performance measurements are not
qualified by these checks. Historical docs/INIT_PROMPT.md is unchanged.

The [migration report](../mcp-sdk-v2-migration.md) preserves the original
investigation, including its corrected description-whitespace comparison error.
The [GitHub Release](https://github.com/onlyxItachi/PerfDigest-MCP/releases/tag/v1.3.0)
records the final CI, trusted-publishing, actual
[PyPI artifact](https://pypi.org/project/perfdigest-mcp/1.3.0/) and post-install
stdio evidence once publication completes.
